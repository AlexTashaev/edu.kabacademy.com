# Спека: запись с рекламных лендов без WordPress (к весеннему набору 2027)

**Дата:** 18.11.2026 · **Статус:** решения владельца приняты 18.11; этап 1 сделан и стоит на dev-edu (18.11), этапы 2–4 не начаты · **v0.2**
**Связано:** разбор для владельца «Ленды без WordPress» (артефакт, 18.11.2026); README
`local_kabsignup` 1.2.0 (ветка `claude/course-registration-flow-d09798`); витрина `local_kabshop`
0.10.0 (линия `claude/kabshop-ru-storefront` = `6160852`); спека вывода WP и опись WP — репо

## 0. Суть

Весной 2027 реклама ведёт на те же статичные ленды на `kabacademy.com/lp/`, но кнопка ленда
(через квиз) ведёт не на чекаут WordPress, а в Moodle:

- бесплатный курс → страница записи `local_kabsignup` (аккаунт + запись одним шагом);
- платный товар → новая страница `local_kabsignup/buy.php`: e-mail → аккаунт → оплата в витрине.

Чтобы новая запись не потеряла ничего из того, что осенью делал WordPress, нужны доработки
ниже: оформление под кампанию, все метки и ответы квиза, метка персоны для гостиной, проверка
адреса, серверное событие для Facebook, путь новичка в витрине, статичные страницы «Спасибо»
и мост в Telegram-бота.

## 1. Решения владельца (18.11.2026)

| № | Решение |
|---|---|
| 1 | Ленды остаются статикой на `kabacademy.com/lp/`. После выключения WP kabacademy.com — хост лендов + перенаправления на edu |
| 2 | Имя и e-mail — на отдельной странице записи в Moodle, оформленной под ленд (как чекаут WP) |
| 3 | Квиз остаётся. Балл и ответы храним. Адрес проверяем на выдуманный (как Clearout на чекауте WP) |
| 4 | «Спасибо» — статичные страницы на `/lp/` с пикселем и кнопкой в гостиную. Гостиные по персонам весной продолжаем |
| 5 | Окно взноса («Безвозмездная помощь») на записи с лендов **не показываем** |
| 6 | Платные ленды к весне будут → путь «e-mail → аккаунт → оплата». Гостя витрины с бесплатного курса ведём на страницу записи |
| 7 | Вся весенняя реклама сразу на новую запись, без деления пополам. Страховка — сверка числа записей с осенью в первые дни и возврат кнопки на чекаут WP при просадке |

Плюс: прод Moodle открываем гостям так же, как dev (главная = витрина, `forcelogin = 0`).

**Следствие решения 6, принятое вместе с ним:** правило 09.11 «аккаунт только вместе с записью
на курс» расширяется до «аккаунт только вместе с записью **или покупкой**». Бросивший оплату
остаётся с пустым аккаунтом; удалять такие аккаунты не будем (войти он может по ссылке на почту
и докупить).

## 2. Что не меняется

- Ленды и квиз собираются и заливаются как осенью (репо kabacademy.com, `landings/`, `lp/`).
  Список меток, которые несут ленд и квиз, тот же (`src/carry.ts`, `PASS_PARAMS`).
- В `local_kabsignup` остаётся всё из 1.2.0: аккаунт только с записью, телефон, город по IP,
  пол, письмо о дублях, «Вы уже записаны», условия записи (часть 2 после части 1),
  рейт-лимит, honeypot, письмо с логином и паролем новичку и ссылкой — существующему.
- Витрина, оплата, окно взноса в витрине для вошедших — без изменений, кроме кнопок для гостя (§5).

## 3. Адреса для кнопок лендов (контракт с лендами)

```
бесплатный курс:  https://edu.kabacademy.com/local/kabsignup/index.php?id=<курс>&camp=<кампания>&<метки>
платный товар:    https://edu.kabacademy.com/local/kabsignup/buy.php?product=<товар>&camp=<кампания>&<метки>
```

`<метки>` — всё, что собрал `carry.ts` (19 ключей), плюс `quiz_score` и `qa` от квиза. Квиз
по-прежнему ставит `pres` (по умолчанию `rav`). В квизе меняется только `CHECKOUT_URL` (или
`<body data-checkout>`), в `go.php` (ветка без JavaScript) — адрес чекаута.

**Сделано 18.11.2026, стоит на dev-edu** (версия 2026111802): ветка
`claude/landings-signup-flow-a70169` = `claude/course-registration-flow-d09798` + `1b06dd5`,
`05e1d5b`, `3066ae4`. Устройство и настройки — README плагина, раздел «Кампании, метки,
персона, пиксель». Проверено на dev: апгрейд 1.2.0 → 1.3.0 (поля журнала, таблица кампаний);
форма в гамме кампании на 1280 и 500 px (логотип, карточка, телефон с флагом по
`CF-IPCountry`, флажок согласия, кнопка и подпись); новый адрес → «Спасибо» персоны
`…/thanks/edik/` с `utm_*`, `camp`, `pres`, `eid`; без персоны → адрес без персоны; без
согласия → ошибка; в журнале все метки, балл, ответы, персона, `eventid`; `kab_persona`
записан; фоновая задача прошла (`geo`); список и форма кампаний, сохранение, «Заявки» и
CSV; в браузере `054 123 4567` при +972 → `+972541234567`. **Не проверено:** событие
Facebook вживую (нужны пиксель, токен и код Test Events в настройках dev — их вписывает
владелец), Clearout вживую (нужен токен), письма (на dev выключены), запись существующего
адреса в режиме «записывать сразу» (на dev стоит «просить войти»). С web-18 оба сервиса
доступны (Graph API 400 без токена, Clearout 401). На dev для проверки созданы кампании
`spring27test` и `spring27pres` и поле профиля `kab_persona` (как на проде).

### 4.1 Кампании — таблица вместо строки настроек

Сейчас кампания — строка `метка|URL «спасибо»` в настройке `campaigns`. Заменяем на таблицу
`local_kabsignup_campaign` и страницу «Кампании» (список + форма), как товары в витрине.
На проде плагина ещё нет, на dev настройка пуста — переносить нечего.

| Поле | Что |
|---|---|
| `slug` | метка `camp` из ссылки, уникальная |
| `courseid` | курс по умолчанию (ссылка может прийти без `id`) |
| `thankyouurl` | адрес «Спасибо»; можно `{pres}` — подставится персона (`…/thanks/{pres}/`) |
| `thankyoufallback` | адрес, если `{pres}` пуст или не из списка персон |
| `title`, `intro` | заголовок и текст над формой |
| `cardtitle`, `cardnote`, `cardimage`, `pricelabel` | карточка курса, как на чекауте WP: «Классическая каббала. Часть 1 · Старт … · 15 недель», «$0» |
| `buttonlabel`, `belowbutton` | «Забронировать место», «Предоплаты нет — сумму вклада вы определите в конце курса» |
| `theme` | цвета (фон, текст, акцент, кнопка, текст кнопки), шрифт заголовков из списка, логотип |
| `capi` | слать ли серверное событие регистрации в Facebook (§4.5), по умолчанию да |
| `visible` | выключенная кампания ведёт себя как ссылка без `camp` |

Без `camp` или с неизвестной меткой страница выглядит как сейчас (нейтральное оформление).

### 4.2 Оформление и форма

- Своя вёрстка страницы (макет без шапки Moodle): логотип, карточка курса, форма, кнопка,
  подпись, строка поддержки. Цвета и шрифт — из кампании, CSS-переменными. Шрифты — только
  самохост на edu (`/kab/fonts/`), не с kabacademy.com: межсайтовые шрифты требуют CORS.
- Сначала телефон (390 px): без горизонтальной прокрутки, поля на всю ширину.
- Поля: имя, фамилия, e-mail, телефон — как сейчас. Телефон с флагом и кодом страны, как на
  чекауте WP (intl-tel-input, копия в плагине, не с CDN); страна по умолчанию — из заголовка
  `CF-IPCountry`, если Cloudflare его даёт, иначе без страны.
- **Согласие с правилами** — обязательный флажок «Я прочитал(а) и принимаю правила и условия»
  со ссылкой из новой настройки `termsurl` (по умолчанию — оферта витрины, если она стоит).
  На чекауте WP он был, в 1.2.0 его нет.
- Те же оформление и подписи — на страницах «Вы уже записаны», «Запись только для
  продолжающих» и на встроенной «Вы записаны».

### 4.3 Метки и квиз — в журнал

- Принимаем все ключи `PASS_PARAMS` + `quiz_score`, `qa` (сейчас — только 5 `utm_*`).
  Чистка: `PARAM_NOTAGS`, до 255 символов (`qa` — только цифры и запятые).
- Журнал `local_kabsignup_log`: новые поля `attribution` (TEXT, JSON принятых ключей),
  `quizscore` (INT, NULL), `persona` (CHAR 32), `eventid` (CHAR 32, случайный, для склейки
  событий Facebook), `productid` (INT, для покупок §5).
- Метки едут в форму и обратно в URL (как сейчас `utm_*`), перезагрузка их не теряет.
- На «Спасибо» уходят: `camp`, `utm_*`, `pres`, `eid` (= `eventid`). Клик-иды и ответы квиза
  на «Спасибо» не передаём — они уже в журнале.
- Журнал хранится `retentiondays` (365), как сейчас; в privacy provider — новые поля.

### 4.4 Персона → гостиная

- `pres` проверяется по списку из новой настройки `personas` (через запятую: `edik, mushi,
  gavriel, senja, rav, itzik`). Не из списка — персоны нет.
- Персона пишется в поле профиля из настройки `personafield` (по умолчанию `kab_persona`)
  через штатный `profile_save_custom_fields()`. Нет такого поля — молча пропускаем.
- Пишем и новому, и существующему аккаунту, перезаписывая старое значение, — как делал WP.
  Это сознательное исключение из правила «существующий аккаунт не трогаем»: метка персоны —
  не данные человека, а выбор гостиной; второгоднику из прошлого потока иначе откроется
  гостиная старой персоны.
- Гостиные нового курса — копии осенних, видимость по `kab_persona` (как в курсе 236).

### 4.5 Серверное событие регистрации для Facebook

Сейчас WP шлёт `CompleteRegistration` дважды: из браузера на «Спасибо» и с сервера (Conversions
API), с общим `event_id`, и только за первую запись человека на курс. Переносим серверную часть:

- После записи со статусом `created`, `enrolled` или `loggedin` (не `already`, не `noprereq`) и
  при `capi = да` у кампании — событие в фоновой задаче `after_signup` (форму не держит).
- `event_id` = `eventid` из журнала; тот же `eid` получает «Спасибо», и браузерное событие
  склеивается с серверным.
- Данные: хеш e-mail и телефона (SHA-256, как в WP), `fbc` из `fbclid` (`fb.1.<время>.<fbclid>`;
  куку `_fbc` с kabacademy.com edu не видит), IP и браузер посетителя из заявки.
- Пиксель и токен — настройки плагина `capipixel`, `capitoken` (берутся из wp-config WP),
  в git не попадают. Пусто — событие не шлётся.

### 4.6 Проверка адреса (Clearout)

- Только для адреса, которого нет в Moodle (существующему — не нужно, экономия проверок).
- Синхронно при отправке формы, таймаут 4 с. Отказ — только при `invalid` и `disposable`;
  `unknown`, «catch-all» и любая ошибка сервиса — пропускаем, в `flags` журнала `co:skip`.
- Текст ошибки: «Проверьте адрес: на него не получится отправить письмо».
- Токен — настройка `clearouttoken` (из настроек плагина Clearout в WP). Пусто — проверки нет.

### 4.7 Выгрузка для аналитики

Страница «Заявки» с фильтром по датам и кампании и выгрузкой CSV: дата, курс, кампания,
статус, новый аккаунт, `userid`, все метки, балл, ответы, персона. Без e-mail и телефона.
Право `local/kabsignup:viewreports` (менеджер). Если аналитике нужен веб-сервис — потом.

## 5. Этап 2 — новичок в витрине

### 5.1 Страница покупки `local_kabsignup/buy.php` (`local_kabsignup` 1.4.0)

- `?product=<id>` + `camp` и метки, как у записи. Товар — видимый товар витрины без условия
  записи (`requirecourses` пусто). Иначе — на страницу товара (там «Войти и купить»).
- Вошедший → сразу на страницу товара.
- Гость видит карточку товара (название, цена из витрины) и ту же форму (§4.2) с кнопкой
  «Перейти к оплате».
- **Новый адрес** → аккаунт (как в записи, без зачисления), автовход, письмо «Ваш аккаунт» с
  логином и паролем, журнал со статусом `account` → на страницу товара.
- **Адрес занят** → аккаунт не трогаем, письмо со ссылкой входа (`auth_kabmagic::issue_link()`
  с `wantsurl` = страница товара), страница «Мы отправили ссылку для входа — по ней вы
  вернётесь к покупке». Статус `exists`.
- Проверка адреса, телефон, город, пол, дубли — как в записи.
- Мягкая зависимость от `local_kabshop`: нет витрины — страница отвечает «покупка недоступна».

### 5.2 Кнопки для гостя в витрине (`local_kabshop`, следующая версия линии)

На странице товара для гостя (`product.php`):

| Товар | Сейчас | Будет |
|---|---|---|
| бесплатный курс | «Войти и записаться» → вход | «Записаться» → `kabsignup/index.php?id=<курс>&camp=shop` |
| платный, без условия | «Войти и купить» → вход | «Купить» → `kabsignup/buy.php?product=<id>&camp=shop` |
| с условием (часть 2) | «Войти и купить» | без изменений |

- Метки из адреса страницы товара пробрасываются в эти ссылки (платный ленд может вести и на
  страницу товара).
- Нет `local_kabsignup` — кнопки как сейчас.
- `local_kabsignup` пускает запись на курс, если он в «Курсах с открытой записью» **или** у него
  есть видимый бесплатный товар витрины, — иначе пришлось бы дублировать 20+ курсов в настройке.
- Правка в линии кассы `claude/kabshop-ru-storefront`, версия — следующая за той, что стоит на
  dev: договориться с сессией витрины, чтобы не разойтись номерами.

### 5.3 Событие покупки для пикселя

Для платных лендов реклама оптимизируется на покупку. Событие `purchase` в Moodle уже в плане
витрины (опись WP п. 13, решение 25.10 — после подъёма на проде) — оно нужно к первому платному
ленду. Здесь не делаем, только зависимость.

## 6. Этап 3 — «Спасибо» и ленды весны (репо kabacademy.com)

- Статичные страницы `lp/<кампания>/thanks/<персона>/` (+ `index.php`-шим, как у лендов),
  по образцу осенних «Спасибо» из WP: клип персоны, «Первое занятие», кнопка «Пройти в гостиную»,

  `/lp/` (wp-content уйдёт вместе с WP).
- Текст один для нового и существующего аккаунта («если вы уже учились у нас, ссылку для входа
  мы прислали на почту»): страница не должна выдавать, был ли адрес в базе.
- Кнопка «Пройти в гостиную» → урок-гостиная нового курса. Новичок уже вошёл; существующий
  попадёт на вход → «Войти по ссылке на почту».
- GTM на странице; `CompleteRegistration` с `eventID = eid` — только если `eid` есть в адресе.
  Повторная запись `eid` не получает (уходит на «Вы уже записаны»), события нет.
- Квиз и ленды весны: `CHECKOUT_URL` → адрес §3; `go.php` → тот же адрес.

## 7. Этап 4 — мост в Telegram-бота без WP (`local_kabtelegram` 0.1, новый плагин)

Сейчас: «Спасибо» WP строит ссылку в бота SendPulse с токеном, данные человека лежат в WP;
вебхук SendPulse приходит в WP, WP пишет боту переменные `kab_*`. Гостиные ходят через
`/kab/tgbot.php` → WP. Без WP — не работает; пока WP жив, для людей из `local_kabsignup` WP
находит только профиль, без телефона и балла квиза.

- `/local/kabtelegram/go.php` (под входом): токен `u<userid>_<случайное>` → таблица
  `local_kabtelegram_token` (снимок: имя, фамилия, e-mail, телефон, страна, город, курс, балл
  квиза из журнала записи, 7 дней) → редирект в бота с `start=<flow>&token=<токен>`.
  Гость (не вошёл) → бот без токена, как сейчас при сбое.
- `/local/kabtelegram/webhook.php`: вебхук SendPulse, проверка секрета в заголовке, токен из
  `contact.variables.token`, запись переменных через API SendPulse (`setVariable`), как в WP.
- Настройки: id и секрет API SendPulse, секрет вебхука, имя бота, flow — из настроек WP, в git
  не попадают.
- В день старта весенней кампании: `/kab/tgbot.php` ведёт на `go.php`; вебхук SendPulse
  переключается на edu (осенние токены к этому времени протухли — живут 7 дней).
- Статистику переходов и подсчёт подписчиков канала (`wp kab-te-stats`) не переносим.

## 9. Изоляция

- Всё своё — в `local_kabsignup` (новые поля журнала, новая таблица кампаний) и новом
  `local_kabtelegram`. Ядро и тему не трогаем.
- `local_kabshop` — только кнопки гостя на странице товара; логика оплаты, условия, окно
  взноса не меняются.
- Существующие аккаунты: по-прежнему только зачисление и письмо со ссылкой; единственное

- Внешние сервисы (Facebook, Clearout, SendPulse) — только из фоновых задач или с таймаутом
  и пропуском при сбое: запись не зависит от их доступности.
- Ключи и токены — только в настройках плагинов, не в git (репо публичное).
