# План облегчения Moodle (ноябрь 2026)

**Решение 24.11.2026:** платформу не менять и не переписывать, а облегчать. Используемая часть
Moodle (тесты, уроки, форумы с уведомлениями, условия доступа, группы и роли тьюторов, приложение)
дороже всего в переписывании, а мешают нам в основном сторонние плагины, лишние данные и отсутствие CLI.

**Цели:**
- меньше сторонних плагинов, которые надо проверять при каждом апгрейде;
- легче база и дампы;
- меньше обходных путей в администрировании.

Нагрузка не цель: крон и сервер не перегружены. Самая тяжёлая задача крона — пересчёт выполнения,
около 2,5 тыс. секунд за неделю.

Все цифры ниже взяты с прода 24.11.2026, запросы только на чтение.

**Если сделать всё:**
- сторонних плагинов станет ~31–33 вместо 46;
- база уменьшится с 10,9 ГБ примерно до 6,5–7 ГБ;
- ещё −3 ГБ файлов, если убрать старые сертификаты;
- апгрейды, чистка кэшей и правка настроек пойдут штатными CLI-скриптами, а не curl-ом и SQL.

## Правила для всех шагов

- Начинать после 1.12.2026, когда устоится уход с WordPress. Курс 236 ни один шаг не задевает.
  Исключение — чистка отметок о прочтении в его форумах, но студенты её не заметят.
- Сначала dev, потом прод. Перед каждым шагом на проде — полный дамп БД и архив каталога плагина.
- Удаление плагина стирает его таблицы и файлы, откат возможен только из дампа. Порядок удаления:
  1. «Администрирование → Плагины → Обзор плагинов → Удалить» (сессия админа с MFA) или
     `admin/cli/uninstall_plugins.php`, когда появится CLI (шаг 6).
  2. Удалить каталог плагина из кода. Если каталог остался на диске, Moodle предложит поставить плагин заново.
  3. «Очистить кэши».
- SQL на проде — только с явного разрешения владельца, ночью, пачками.
- После удаления плагина: убрать его каталог из репо (если он там лежит), поправить строку в реестре
  `CLAUDE.md` и в списке аудита `probe_moodle.sh` (если она там есть).

## Шаг 4. База: минус 4–4,5 ГБ из 10,9

| Что | Сейчас | Что сделать |
|---|---|---|
| `forum_read` — отметки «прочитано» на форумах | 23 млн строк, 2,9 ГБ, в основном 2023–2024 годов | В Moodle 5.1 функция чистки `forum_tp_clean_read_records()` есть, но её никто не вызывает: проверено по всему коду 5.1.9, задача `\mod_forum\task\cron_task` её не зовёт. Поэтому таблица растёт без конца. Отметки к сообщениям старше `forum_oldpostdays` (у нас 14 дней) не нужны: такие сообщения Moodle и так показывает прочитанными. Первая чистка — SQL пачками ночью (черновик ниже), потом `OPTIMIZE TABLE`: дамп уменьшится сразу, файл таблицы — только после него. Дальше чистку раз в сутки делает задача по расписанию в маленьком плагине `local_kabmaint`, а не патч ядра. Проверить трекер Moodle и завести задачу, если её там нет |
| `grade_grades_history` | 9,7 млн строк, 2 ГБ, с 2018 года; срок хранения — «никогда» | Поставить «Оценки → Общие настройки → Срок хранения истории оценок»: 1000 дней (база потеряет примерно половину таблицы) или 365 (примерно ¾). Первый проход сделать SQL пачками, чтобы суточная задача не удаляла миллионы строк одним запросом |
| `analytics_*` | 1,85 млн строк, 218 МБ; аналитика выключена | Очистить таблицы предсказаний: сначала их бэкап, потом `TRUNCATE`. `analytics_models` и `analytics_models_log` не трогать |
| `stats_*` | 0,95 млн строк, 96 МБ; статистика включена, но отчёт за 30 дней никто не открывал | Выключить `enablestats`, данные удалить |
| `_kab_bk*` — наши страховочные копии таблиц | 171 таблица, 5 МБ, самые старые от 09.09.2026 | Раз в квартал удалять копии старше 30 дней |

Мелочи в настройках, которые возвращаются одной галочкой:
- выключить «Результаты обучения» (`enableoutcomes`): их ноль;
- выключить «Заметки» (`enablenotes`): всего 20, за год ни одной новой;
- в `mod_hvp` выключить отправку статистики и H5P Hub.

Черновик SQL для первой чистки. Сначала на dev; префикс `mdl_`.

```sql
-- forum_read: отметки к сообщениям старше 14 дней, пачками по 200 тыс. id
-- (id от ~0,9 млн до ~93 млн, строк 23 млн; DELETE с JOIN не принимает LIMIT, поэтому идём диапазонами)
DELETE fr FROM mdl_forum_read fr
  JOIN mdl_forum_posts fp ON fp.id = fr.postid
 WHERE fr.id BETWEEN @a AND @a + 199999
   AND fp.modified < UNIX_TIMESTAMP() - 14*86400;

-- история оценок до выбранного порога, пачками
DELETE FROM mdl_grade_grades_history WHERE timemodified < @cutoff LIMIT 100000;
```

## Шаг 6. CLI Moodle

Сейчас штатные скрипты `admin/cli/*` не запускаются: пользователю SSH каталог данных доступен
только на чтение. Отсюда обходные пути:
- апгрейды — цепочкой curl через веб;
- кэши — только из админки;
- настройки, которые режет WAF Cloudflare («Дополнительный HTML»), — SQL-ом.

Открыть каталог данных на запись для группы нельзя: файлы кэша, созданные из CLI, окажутся не от
пользователя веб-сервера. Нужен запуск CLI именно от пользователя веб-сервера — через узкое правило
sudo или через обёртку. Заявку сисадмину владелец отправляет со своего ящика; текст в этот публичный
репозиторий не кладём, потому что в нём адреса и пользователи сервера.

Что даст CLI:
- `uninstall_plugins.php` — шаги 1–2 без сессии админа;
- `purge_caches.php`;
- `upgrade.php --non-interactive` и `maintenance.php` — апгрейд без curl;
- `cfg.php` — настройки без админки и без WAF;
- `scheduled_task.php --execute=…` — прогнать задачу по требованию;
- `check_database_schema.php`.
