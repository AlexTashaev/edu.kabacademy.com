# Ежедневные отчёты кассы секретарю — спека (26.11.2026)

## Зачем

В WordPress плагин Advanced Order Export каждое утро слал секретарю (копия — поддержке)
Excel с **новыми** оплаченными заказами, пустые файлы не слал. Живых выгрузок три:

| Выгрузка WP | Что в неё попадало |
|---|---|
| «Заказы ОК <поток>» | заказы курса ОК текущего потока (категория товаров потока, на каждый поток — новое задание) |
| «Взносы за ОК» | «Взнос за курс Основы каббалы» (часть 1 и часть 2) |
| «Взносы в фонд МАК» | разовый и ежемесячный взнос, «Пожертвование» (с продлениями подписки) |

Касса Moodle (`local_kabshop`) с 23.11 принимает взносы, но отчёт секретарю не шлёт:
взносы, сделанные в кассе, до секретаря не доходят. С выключением WordPress пропадут и
выгрузки WP. Нужна та же рассылка из Moodle.

## Что делаем

Задача по расписанию `\local_kabshop\task\send_staff_reports` — раз в сутки (06:05 по
времени сервера). Для каждого отчёта из настройки берёт **новые** покупки кассы (после
прошлой отправки), со статусом `ok`, по товарам отчёта, и шлёт каждому получателю письмо
с файлом `.xlsx`. Нет новых покупок — письма по этому отчёту нет.

### Настройки (Плагины → Локальные плагины → «Витрина: отчёты секретарю»)

- `staffreportemails` — получатели через запятую. **Пусто — отчёты выключены** (значение
  по умолчанию; на проде вписать вручную после установки).
- `staffreports` — отчёты, по одному на строку: `Тема письма | товары`. Товары — id через
  запятую, `s<id>` — все товары раздела витрины (новый товар потока в разделе попадает в
  отчёт сам, без правки настройки). Пока не сохранено — по умолчанию:
  ```
  Заказы ОК | s1, s2
  Взносы за курс ОК | s12
  Взносы в фонд МАК | s7
  ```
  (прод: раздел 1 «Начать обучение» — ОК часть 1, 2 «Продолжить обучение» — часть 2 и
  повторное прохождение, 12 «Плати сколько хочешь» — взносы за курс, 7 «Поддержать академию» —
  взносы в фонд).

### Что считается «новым»

Метка `local_kabshop/staffreportslastid` — номер последней покупки, уже разобранной по
отчётам. Запуск берёт покупки с `id` больше метки и не больше максимального на момент
запуска, раскладывает по отчётам, отправляет и сдвигает метку — только если все письма
ушли (`email_to_user` вернул true); иначе в следующий раз отправка повторится.
**Первый запуск** (метки нет) берёт все покупки кассы с открытия (23.11.2026) — взносы,
которые секретарь ещё не видел. Отчёты выключены (нет получателей) — метка не двигается.

### Столбцы файла

Номер заказа · Дата (время сервера) · Имя · Фамилия · Moodle id · Email · Телефон ·
Город · Страна · Часовой пояс · Пол (поле профиля `gender`, local_kabgender) · Товар ·
Сумма · Валюта · Скидка · Промокод · Вид (оплата, бесплатно, автоплатёж, вручную) ·
Способ оплаты · Номер в сервисе оплаты · Транзакция.

Нет, хотя было в WP: ответы квиза, UTM-метки, IP — касса их не хранит. Налоговые данные
жертвователя (тип, номер) в письмо **не кладём**, как и WP: квитанцию выдаёт сервис оплаты
по данным, переданным при оплате; номера удостоверений по почте не рассылаем.

### Страница «Отчёты секретарю» (`/local/kabshop/staffreports.php`, право `local/kabshop:manage`)

Список отчётов, сколько новых покупок уйдёт в следующий раз, кнопка «Скачать» (тот же
файл, без отправки и без сдвига метки) и «Отправить сейчас» (sesskey; то же, что задача).
Нужна для проверки на dev (там письма не уходят — `noemailever`) и для разовой отправки.

## Изоляция

- Новый класс `classes/staffreports.php`, задача `classes/task/send_staff_reports.php`,
  страница `staffreports.php`, строки языка, настройки. Покупки, оплаты, подписки,
  выдача доступа и письма покупателям не меняются; схема БД не меняется.
- Читает: `local_kabshop_purchase`, `_product`, `_coupon`, `payments`, `paygw_kbb1`
  (если есть), `user`, `user_info_data`/`user_info_field` (`gender`). Пишет: одну
  настройку-метку.
- Откат: удалить получателей в настройке (отправка прекращается сразу) или выключить
  задачу в «Задачах по расписанию».

## Внешние зависимости

- Почта Moodle (SMTP SendGrid), заголовок `X-SMTPAPI` с категорией `moodle-shop-report`.
- `core\dataformat` с форматом `excel` (ядро) — файл пишется во временный каталог запроса,
  вложение `email_to_user` берёт его оттуда.
- Cron Moodle (задачи по расписанию на проде идут: `charge_subscriptions` каждый час).

## Проверка

dev: страница отчётов — числа совпадают с выборкой SQL; «Скачать» даёт открываемый xlsx с
нужными столбцами; «Отправить сейчас» при пустых получателях ничего не шлёт и метку не
двигает, с получателем — метка сдвигается, повтор ничего не шлёт. Прод: вписать
получателей, «Отправить сейчас» — первое письмо со взносами с 23.11; утром — письма от
задачи только с новыми покупками.
