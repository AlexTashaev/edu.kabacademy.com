# Купоны по адресам e-mail и «кто использовал» — local_kabshop 0.9.0

18.11.2026. Запрос владельца: «выдачу купона по мейлу, и не один мейл, а много; хорошо бы видеть,
кто использовал купоны».

## Что есть сейчас (0.8.0)

- Купон = код + скидка (% или сумма) + товары + срок + лимит + «один раз на человека».
- Использования пишутся в `local_kabshop_coupon_use` и в заказ (`purchase.couponid`); в «Заказах»
  код купона виден в колонке «Тип», но фильтра по купону нет, поиск по коду не ищет. В списке
  купонов — только число использований.
- Привязки к людям нет: код работает у любого, кто его знает. Рассылки кода нет.

## Что меняется

### 1. Адреса у купона

- Новое поле формы купона «Адреса e-mail» — сколько угодно адресов, через запятую, пробел или с новой
  строки. Неверный адрес — ошибка формы с перечислением. Хранятся в нижнем регистре в новой таблице
  `local_kabshop_coupon_email` (couponid, email, timesent, timecreated; уникальный couponid+email).
- Галочка «Только для этих адресов» (`coupon.emailonly`, по умолчанию включена): купон применяется
  только у пользователя, чей e-mail в аккаунте есть в списке (без учёта регистра). Остальным — «Этот
  промокод выдан на другой адрес». Пустой список — ограничения нет, как раньше.
- Удалённый из списка адрес теряет право на купон; уже оформленные заказы не трогаются.

### 2. Письмо с промокодом

- Галочка «Отправить промокод письмом на адреса, которым ещё не отправляли» (по умолчанию включена).
  При сохранении ставится adhoc-задача `send_coupon_emails`: письма уходят с cron, а не во время
  сохранения формы, поэтому сотни адресов не подвесят страницу. Кому отправлено — `timesent`;
  повторно не шлём. Новый адрес, добавленный позже, получит письмо при следующем сохранении с галочкой.
- Получатель: аккаунт Moodle с этим e-mail (обращение по имени), иначе письмо на голый адрес
  (подставной пользователь, как в формах поддержки ядра) с обращением «Здравствуйте!».
- Текст: код, размер скидки, на какие товары, срок, ссылка (страница товара, если товар один, иначе
  каталог), как применить («Есть промокод?» на странице товара), при «только для этих адресов» —
  что войти надо под этим адресом.
- Под полем адресов в форме — «Письма отправлены: X из Y».

### 3. Кто использовал

- «Заказы»: фильтр «Промокод» (список купонов), поиск по строке ищет и по коду купона.
- «Купоны витрины»: число использований — ссылка на «Заказы», отфильтрованные по этому купону
  (оттуда же выгрузка CSV); новая колонка «Адреса» — «N, отправлено M», пометка «только им».

## Изоляция и внешние зависимости

- Только `local_kabshop`: таблица `local_kabshop_coupon_email`, поле `local_kabshop_coupon.emailonly`,
  adhoc-задача. Шлюзы, ядро и другие плагины не трогаем.
- Внешнее — только почта (штатный `email_to_user`, на проде SendGrid). На dev `noemailever` —
  письма не уходят, задача отмечает отправку; текст проверяется в журнале задачи.
- Права: форма и рассылка — `local/kabshop:manage`, как и сейчас.
- Privacy: адреса купонов — персональные данные; описаны в provider.

## Проверка на dev

1. Купон с двумя адресами (один — аккаунт админа, другой — чужой), «только для этих адресов»:
   у админа применяется; после удаления его адреса из списка — «выдан на другой адрес».
2. Ошибка формы на неверном адресе; дубли и регистр схлопываются.
3. Сохранение с галочкой письма — adhoc-задача, после cron `timesent` проставлен, в форме
   «отправлены 2 из 2»; повторное сохранение писем не дублирует.
4. «Заказы»: фильтр по купону и поиск по коду; ссылка из списка купонов ведёт на отфильтрованные заказы.
