# Взнос при бесплатной записи (попап) — local_kabshop 0.10.0

18.11.2026. Запрос владельца: «сделать попап при записи на бесплатные курсы с предложением сделать
взнос или отказаться от взноса (как было на кабакадеми)».

## Как сделано на WordPress (прод, проверено 18.11.2026)

- Тема `kabacedemy`: `functions.php` → `add_donation_checkout_modal()` (хук `wp_head`) и шаблон
  `template-parts/donation-popup-checkout.php`.
- Срабатывает **только на странице корзины WooCommerce**, когда сумма корзины 0, то есть в корзине
  бесплатный курс. Чекауты CartFlows, через которые идут ленды, попапа не показывают.
- Окно появляется через 3 с после загрузки корзины:
  - текст из ACF-опции `donation_popup_title`: «Весной 2027 мы делаем новый набор студентов. Мы очень
    хотим, чтобы он остался со свободным доступом. Помогите нам сделать это. Без Вас у нас не
    получится.»;
  - подпись «Безвозмездная помощь»;
  - суммы — вариации товара 406587 «Пожертвование» (USD): $20, **$90 по умолчанию**, $250,
    «другая»;
  - кнопка «Карты Visa, Mastercard, Paypal» кладёт пожертвование в корзину, и оно оплачивается
    вместе с записью.
- Отказ — крестик: окно закрывается, бесплатная запись продолжается как обычно.

## Что делаем в Moodle

Аналог корзины WP в Moodle — кнопка «Записаться бесплатно» на странице товара витрины. Попап
вешается на неё. Запись с лендов (`local_kabsignup`) попап не получает: на WP чекауты лендов его тоже
не показывали. Если понадобится — отдельная задача: страница «спасибо» kabsignup.

### Когда показывается

Должно выполняться всё:

1. На странице стоит кнопка «Записаться бесплатно». Это значит: товар бесплатный и не внешний,
   человек вошёл, прошёл условие записи и ещё не записан.
2. В настройках выбран товар-пожертвование (`local_kabshop/freedonation_product`). Он видимый, вид
   «Пожертвование», с суммой на выбор, с подключённым счётом оплаты, и условие записи у него не мешает.
3. Рынок пожертвования совпадает с рынком бесплатного товара: на рублёвой витрине предлагается только
   рублёвое пожертвование. Robokassa пожертвований не принимает, поэтому на деле попап есть только на
   основной витрине.
4. У человека нет активной подписки на пожертвование: ежемесячного жертвователя не просим ещё раз.

Без JavaScript кнопка работает как раньше: бесплатная запись без окна.

### Окно

- Заголовок «Безвозмездная помощь».
- Текст из настройки `freedonation_text` (HTML). По умолчанию — текст WP.
- Суммы — настройка `freedonation_presets`, по умолчанию «20, 90, 250», в валюте
  товара-пожертвования. Выбрана заранее сумма из `freedonation_default` (90). Суммы меньше минимума
  товара-пожертвования и больше `MAX_AMOUNT` отбрасываются. Если не осталось ни одной — берутся
  пресеты самого товара.
- «Или своя сумма» — поле ввода. Если оно заполнено, побеждает его значение (как в `donate.php`).
- Кнопки: **«Записаться и сделать взнос»** — основная, **«Записаться без взноса»** — вторая, тише.
  Крестик и Esc только закрывают окно, ни записи, ни взноса.
- Окно — нативный `<dialog>`: фокус внутри, Esc, затемнение фона. Ни Bootstrap-модалок, ни AMD.

### Что происходит после выбора

Обе кнопки отправляют одну форму на `enrol.php`; поле `donate` равно 1 или 0.

- **Без взноса** — как сейчас: запись, переход в курс, «Вы записаны».
- **Со взносом** — сначала запись. Бесплатная запись не зависит от оплаты: бросил оплату —
  всё равно записан. Дальше:
  - сумма проверяется как в `donate.php`: от минимума товара до `MAX_AMOUNT`. Если сумма неверна —
    переход на страницу пожертвования с ошибкой «Укажите сумму от … до …»;
  - пожертвованию не в рублях нужны данные для квитанции. Если они есть с прошлого пожертвования
    (`catalog::last_tax`), сразу создаётся намерение с ними и открывается окно оплаты. На странице
    видно «Данные для квитанции: …» и ссылку «Изменить пожертвование». Если данных нет — страница
    пожертвования с уже выбранной суммой (через `$SESSION->local_kabshop_tax`, как после ошибки в
    `donate.php`): человек выбирает страну и тип, вводит номер и нажимает «Продолжить» → окно оплаты;
  - рублёвому пожертвованию данные не нужны: сразу намерение и окно оплаты;
  - сверху сообщение: «Вы записаны на курс «…». Спасибо, что решили помочь — осталось оплатить
    взнос.»;
  - курс запоминается в сессии (`$SESSION->local_kabshop_aftercourse`). На странице
    товара-пожертвования до и после оплаты есть ссылка «Перейти к курсу «…»». После оплаты
    `get_success_url` пожертвования ведёт на `product.php?paid=1` («Спасибо! Оплата получена.»); там
    ссылка показывается в последний раз, и запись из сессии стирается.

### Учёт

Новых таблиц нет. Взнос — обычный заказ товара-пожертвования, виден в «Заказах» (SKU и данные
жертвователя — как у любого доната, 0.8.0). Отказ не пишется никуда.

### Настройки

Страница «Витрина: взнос при бесплатной записи» (Администрирование → Плагины → Локальные плагины):

| Настройка | По умолчанию | |
|---|---|---|
| `freedonation_product` | 0 — «Не предлагать» | список видимых пожертвований с суммой на выбор и со счётом |
| `freedonation_text` | текст WP | HTML-редактор |
| `freedonation_presets` | `20, 90, 250` | через запятую или пробел |
| `freedonation_default` | `90` | если не совпадает ни с одной суммой, выбрана первая |

По умолчанию попап выключен. На dev включается товаром № 21 «Пожертвование» (USD, счёт kbb1).

### Файлы

- `classes/catalog.php` — `free_donation_offer($product, $userid)` (условия 2–4, суммы) и
  `has_donation_sub($userid)`.
- `product.php` — данные окна в ветке «Записаться бесплатно»; ссылка «Перейти к курсу» на странице
  пожертвования.
- `enrol.php` — `donate=1`: сумма, намерение или страница пожертвования.
- `templates/product.mustache` — `<dialog>` и JS.
- `styles.css` — окно.
- `settings.php`, `lang/{en,ru}` — настройки и строки.
- `version.php` — 2026111900, 0.10.0. Схема БД не меняется.

## Проверка на dev

1. Настройки: `freedonation_product` = 21 (SQL в `config_plugins` до апгрейда, кэш сбросит апгрейд).
2. Тестовый пользователь без пожертвований: страница бесплатного товара → в HTML есть `<dialog>`,
   суммы 20/90/250 USD, выбрано 90.
3. POST `enrol.php` с `donate=0` → запись, редирект в курс.
4. Другой бесплатный товар, POST с `donate=1&preset=90` → запись, редирект на товар 21. Сумма 90
   выбрана, форма данных жертвователя на месте, ссылка «Перейти к курсу».
5. То же после пожертвования с данными (есть `last_tax`) → редирект с `intent=…`, намерение на 90 USD
   с теми же данными.
6. `donate=1&customvalue=0.5` → редирект на товар 21 с ошибкой суммы, но запись есть.
7. Пользователь с активной подпиской на пожертвование → окна нет.
8. Рублёвый бесплатный товар → окна нет.
9. Внешний вид окна: десктоп и 375 px.

Тестовые записи, намерения и сессии после прогона убрать.

## На прод

Вместе с кассой (витрина ещё не на проде). После установки: «Витрина: взнос при бесплатной
записи» → выбрать товар-пожертвование (на WP это 406587, в Moodle — товар-пожертвование основной
витрины в USD), проверить текст и суммы.
