# local_kabshop 0.12.0: один товар — две валюты, «Взнос за курс», страница курса

19.11.2026. Решения владельца: одна запись с двумя ценами (а не пары товаров по рынкам);
«Взнос за курс» — как покупка курса, без данных для квитанции; страница курса — в стиле
страницы курса kabacademy.com (`/product/osnovy-kabbaly-chast-1-osen-2026/`).

## 1. Две цены у одного товара

**Было:** товар = одна цена + валюта + счёт. Рублёвая цена — отдельный товар-«пара» того же
курса (`catalog::twin()`), на странице товара вторая кнопка «Оплатить в рублях» уводила на
пару. У пожертвований пары нет вовсе (нет курса) — пожертвование из окна при бесплатной
записи платилось только в $.

**Стало:** у товара основная цена (как было: `price`, `currency`, `presets`, `accountid`) и
необязательная вторая:

| Поле | Что |
|---|---|
| `altcurrency` char(3), null | валюта второй цены; пусто — второй цены нет |
| `altprice` number(12,2) | цена (у суммы на выбор — минимум) |
| `altpresets` char(255) | готовые суммы во второй валюте |
| `altaccountid` int | платёжный счёт второй валюты (рубли — Robokassa) |

Всё остальное у товара общее: вид, курс, условие записи, подписка (`recurmonths`), SKU,
описание, картинка.

**Вариант** — товар «в валюте»: копия записи, где `price/currency/presets/accountid`
подменены второй ценой (`catalog::variant($product, $currency)`, `catalog::variants()`).
Почти весь код работает с вариантом как с прежним товаром: цена, минимум, суммы на выбор,
купон, данные для квитанции (`needs_taxid` — по валюте варианта), запись курса, подписка.

### Оплата

- Основная цена, фиксированная — зона `product` (как было).
- Вторая цена, фиксированная — новая зона `productalt`, `itemid` = id товара.
- Сумма на выбор, купон, данные жертвователя — зона `custom` (intent), валюта intent
  определяет вариант.
- Автосписание — `renewal`, валюта подписки определяет вариант.
- `service_provider::resolve()` возвращает вариант → `get_payable` отдаёт сумму, валюту и
  счёт нужной кассы. kbb1 находит товар по `itemid` для любой зоны, кроме custom/renewal —
  `productalt` ему подходит без правок.

### Где выбирается валюта

- Страница товара: переключатель «₽ Рубли · Robokassa | $ Доллары · карта, PayPal»
  (ссылки `?cur=RUB` / `?cur=USD`), виден только у товара с двумя ценами. Выбор
  запоминается в сессии (`$SESSION->local_kabshop_market`).
- По умолчанию: явный `cur` → рынок из сессии (зашёл через `/ru.php` — рубли) → основная.
- С выбранной валютой меняются цена, кнопки, суммы на выбор, продавец и оферта внизу.
- Каталог: `/local/kabshop/` — цены основной валюты, `/ru.php` — рублёвые (товары, у
  которых есть рублёвый вариант), карточки ведут на товар с `cur`.
- Окно «Безвозмездная помощь»: если у товара-пожертвования есть вторая цена — переключатель
  валют над суммами; суммы в рублях — новая настройка `freedonation_altpresets` (пусто —
  суммы самого товара), выбранная заранее — `freedonation_altdefault`. Рубли выбраны
  заранее, если человек пришёл через `/ru.php` или выбирал рубли.
- Кнопка «Поддержать академию» в шапке ведёт на тот же товар — там переключатель.

### Изоляция

- Схема: только новые поля, старые не трогаются. Upgrade-шаг добавляет поля.
- Пары на dev сливаются руками (SQL, разовый): прод не тронут — плагина на проде нет.
  - 42 (₽) → 1, 46 (₽) → 22 и копия его цены в 21 («Пожертвование» — товар окна и
    кнопки шапки), 53 (₽, ежемесячно) → 23 (23 становится ежемесячным и в $, через kbb1),
    52 (₽) → 50. Заказы, intent и подписки слитых товаров переводятся на основной товар,
    валюта в них своя и не меняется. 51 (₽, пары нет) остаётся рублёвым товаром.
- `twin()` и «Оплатить в рублях / картой» уходят. Рублёвый товар без второй цены
  (валюта основной цены — рубли) работает как раньше, только на `/ru.php`.

### Внешние зависимости

- core_payment: зона `productalt` — обычная зона компонента, модалка шлюзов сама берёт
  кассы под валюту счёта.
- paygw_kbb1: `kabshop_product()` для `productalt` берёт товар по `itemid` — правки не нужны.
- paygw_robokassa: через `helper::get_payable` — правки не нужны.

## 2. «Взнос за курс»

Новый вид `contribution`: записывает на курс (если указан), сумма всегда на выбор
(`customamount` ставится сам), не меньше минимума, без данных для квитанции, SKU и
признака пожертвования. Купон не применяется (как к сумме на выбор). На dev
«Взнос за курс…» 50, 51, 52 переводятся в этот вид.

## 3. Страница курса в стиле kabacademy.com

По образцу страницы курса сайта:

- **Шапка курса** — светло-голубая полоса: слева ленточка с названием раздела витрины
  (прописные фиолетовые с разрядкой, белая ленточка с вырезом), название курса крупно
  (Montserrat 700, прописные), под ним «Коротко»; справа обложка товара, растворяется
  к тексту. Без обложки — фирменный узор.
- **Карточка покупки** слева, наезжает на шапку, в рамке-градиенте голубой → фиолетовый
  (как «НАЧАЛО — 1 ОКТЯБРЯ» на сайте): переключатель валют, цена (фиолетовая, прописные
  с разрядкой), фиолетовая кнопка, суммы на выбор, промокод, сообщения. На компьютере
  липнет при прокрутке.
- **Описание** справа: нумерованные списки — сетка в две колонки с номерами в голубых
  квадратах («В программе курса»), маркированные — голубые квадраты со стрелкой
  («Особенности обучения»), пустые абзацы из WordPress скрыты.
- Заголовок страницы Moodle визуально скрыт (остаётся для чтения с экрана), хлебные
  крошки на месте.
- Телефон: шапка в столбик (обложка сверху), карточка во всю ширину, описание ниже.
- Внизу — продавец, контакты и оферта выбранной валюты; оферта и политика открываются
  в новой вкладке (правка 19.11, и в каталоге).
