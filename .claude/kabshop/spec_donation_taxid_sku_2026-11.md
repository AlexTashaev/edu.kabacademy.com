# Пожертвования в витрине: SKU товара и данные жертвователя для квитанции (17.11.2026)

local_kabshop 0.8.0 + paygw_kbb1 0.3.0. Цель — чтобы пожертвование, оплаченное в Moodle картой или
PayPal, приходило в кассу (а через неё в Priority) так же, как из WordPress.

## Как это сделано в WordPress (образец)

- **SKU.** Шлюз `woocommerce-bb` берёт SKU из товара, а если в товаре пусто — SKU по умолчанию из
  настроек шлюза (`order_sku()`). У курсов, иврита, книг, AI-ассистента в товаре стоит свой SKU,
  у товаров-пожертвований SKU пустой — они уходят с SKU шлюза по умолчанию.
- **Признак пожертвования.** Товар в категории `donation` → в запросе `VAT=Y`, `TaxType`, `TaxId`
  (`build_payload()`); у остальных `VAT=N` и пустые поля.
- **Данные жертвователя** (тема `kabacedemy`, `add_cartflow_checkout_hidden_field`,
  `prevent_login_registration`, сохранение в мету заказа `tax_customer_type`, `tax_id_code`):
  - страна (по умолчанию — по IP);
  - для Израиля — тип жертвователя: `1` частное лицо (удостоверение личности), `2` компания /
    организация (регистрационный номер), `9` иностранный резидент (паспорт); по умолчанию `1`;
  - номер — для типов 1 и 2, обязателен, ровно 9 цифр (поясняющий текст про статью 46 и 2026 год);
  - не Израиль или тип 9 → тип `9`, номер `888888888`; Израиль без номера → `999999999`
    (при включённой проверке не случается);
  - автосписания наследуют тип и номер первого заказа (плагин pelecard-additional).

## Что меняется в Moodle

### 1. SKU товара (local_kabshop + paygw_kbb1)

- Поле товара `sku` (char 64, пусто = не задан), в форме товара — «SKU» с подсказкой.
- paygw_kbb1 `build_payload`: `SKU` = SKU товара, иначе SKU по умолчанию из настроек счёта
  «Карта / PayPal» (как `order_sku()` в WP). Автосписания — тот же товар, тот же SKU.
- Robokassa SKU не использует — не трогаем.

### 2. Данные жертвователя

Касается товаров вида «Пожертвование» не в рублях (рублёвые идут через Robokassa российскому фонду,
израильский налоговый зачёт к ним не относится) — `catalog::needs_taxid()`.

- **Страница товара.** Вместо кнопки «Купить» — форма: сумма (готовые суммы и своя — если у товара
  «Сумма на выбор»; иначе просто цена), страна, тип жертвователя и номер. Тип и номер видны только
  при стране «Израиль», номер — только для типов 1 и 2 (JS; без JS видно всё, решает сервер).
  Значения по умолчанию — из последнего пожертвования этого человека, иначе страна из профиля.
- **Проверка и нормализация** — `catalog::clean_tax()` по правилам WP выше. Ошибка — назад на
  страницу товара с сообщением; введённое не теряется (сессия, не адрес: номер — персональные данные).
- **Хранение.** Выбор суммы (`local_kabshop_intent`) получает `taxcountry`, `taxtype`, `taxid`;
  пожертвование с фиксированной ценой тоже идёт через intent (зона оплаты `custom`). После оплаты тип
  и номер пишутся в заказ (`local_kabshop_purchase`) и в подписку (`local_kabshop_sub`), если товар
  регулярный, — автосписания наследуют их, как в WP.
- **Перед оплатой** под кнопкой видна строка «Данные для квитанции: …» и ссылка изменить.
- **Промокоды** к таким пожертвованиям не применяются (форма не показывается, `coupon.php` не пускает):
  купон создаёт intent без данных жертвователя.
- **paygw_kbb1:** для пожертвований `TaxType`/`TaxId` берутся из intent (зона `custom`) или из подписки
  (зона `renewal`); `VAT=Y` — как было.
- **Заказ в админке** показывает «Жертвователь»: тип и номер.
- Privacy: поля `taxtype`, `taxid` заказа добавлены в метаданные.

### Изоляция и внешние зависимости

- Код: только `local/kabshop` и `payment/gateway/kbb1`. WP, Robokassa, ядро — без изменений.
- БД: новые необязательные поля в 4 таблицах витрины (`product.sku`; `intent.taxcountry/taxtype/taxid`;
  `purchase.taxtype/taxid`; `sub.taxtype/taxid`), без переноса данных. Откат — прежние файлы, лишние
  поля не мешают.
- Внешняя зависимость — касса принимает `SKU`, `VAT`, `TaxType`, `TaxId` (те же поля, что шлют из WP).
  Что они дошли до Priority, видно только в кассе/Priority — нужна одна тестовая оплата $1.

### Настройка после выкладки

- В товарах-пожертвованиях — SKU пожертвований (как SKU по умолчанию шлюза в WP), либо наоборот:
  SKU по умолчанию счёта = SKU пожертвований, а SKU курсов прописан в товарах-курсах. Коды — в
  настройках шлюза `woocommerce-bb` на kabacademy.com (в этом публичном репо их не пишем).
