# auth_kabmagic — «Вход по ссылке на почту»

Moodle-родная замена magic-ссылке WordPress (`kab-magic-link-auth`): студент на
странице входа нажимает «Войти по ссылке на почту», вводит e-mail аккаунта и получает
письмо с одноразовой ссылкой, по которой входит без пароля. Нужен, потому что вход
переносится с kabacademy.com на сам Moodle, а ~55 тыс. аккаунтов с `auth = manual`
своих паролей не знают (их заводил Edwiser Bridge).

## Потоки

**A. Запрос ссылки** — `auth/kabmagic/request.php?wantsurl=…`

1. Кнопка на странице входа (`loginpage_idp_list()` плагина; появляется только когда
   плагин включён в «Управлении аутентификацией») ведёт на форму с одним полем e-mail.
   `wantsurl` берётся из параметра кнопки, иначе из `$SESSION->wantsurl`; принимается
   только адрес внутри `$CFG->wwwroot` (`PARAM_LOCALURL`).
2. Форма проверяет только синтаксис адреса. Дальше `manager::request()`:
   - рейт-лимит: не больше `ratelimit` (3) запросов на адрес за `ratewindow` (5) минут,
     на IP — в 10 раз больше; лишние запросы молча отбрасываются (строка в БД не пишется);
   - поиск пользователя: `email` без учёта регистра, `deleted = 0`, `suspended = 0`,
     `confirmed = 1`, локальный (не MNet), `auth` из списка `allowedauths`
     (по умолчанию `manual,email`; `nologin` исключён всегда). Если адрес у нескольких
     живых аккаунтов (`allowaccountssameemail`) — берётся тот, где `lastaccess` свежее;
   - адрес никому не принадлежит → строка с `userid = 0` (считается в лимите), письма нет;
   - иначе токен = 32 случайных байта (`random_bytes`), в БД только `SHA-256`, в письмо —
     base64url (43 символа) в `login.php?t=…`; письмо через `email_to_user` на языке
     пользователя, с одной ссылкой.
3. Ответ всегда один: «Если такой адрес есть, письмо со ссылкой для входа отправлено».

**B. Вход по ссылке** — `auth/kabmagic/login.php?t=<token>`

1. GET из письма: токен ищется по хешу (`peek()`): есть, не использован, не старше
   `lifetime` (15) минут. Иначе — «Ссылка недействительна…» и кнопка «Запросить новую».
   Токен на GET **не гасится**: антивирусы и почтовые сканеры (Outlook Safe Links и т. п.)
   открывают ссылки из писем, и одноразовый токен умирал бы у них в руках. Страница
   показывает форму с кнопкой «Войти», которая сама отправляется скриптом (POST, `sesskey`).
2. POST с `confirm=1`: `require_sesskey`-проверка (без cookie — страница про cookie),
   `consume()` помечает строку использованной (`timeused`), заново проверяет аккаунт
   (те же условия, что при выдаче), затем `complete_user_login()`,
   `apply_concurrent_login_limit()`, снятие lockout (почта — это и есть то, что проверяет
   штатное письмо разблокировки), cookie с логином, редирект через
   `core_login_get_return_url()` на `wantsurl`, иначе на `/my/`.
3. Если в браузере уже открыта сессия того же пользователя — просто редирект на `wantsurl`
   (токен гасится). Если другого — тот же диалог «Вы уже вошли как …» с кнопкой «Выход»,
   что и на штатной странице входа; после выхода ссылку надо открыть ещё раз.

**C. Чистка** — задача `auth_kabmagic\task\cleanup_tokens` раз в сутки (03:40)
удаляет строки старше `max(lifetime, ratewindow) + 1 день`.

## Таблица БД `auth_kabmagic_tokens`

| Поле | Тип | Что |
|---|---|---|
| `userid` | int | кому выдана ссылка; `0` — адрес никому не принадлежит (строка только для лимита) |
| `emailhash` | char(64) | SHA-256 введённого адреса в нижнем регистре (для лимита; сам адрес не хранится) |
| `tokenhash` | char(64) | SHA-256 токена; пусто, если ссылка не выдавалась. Сам токен не хранится нигде |
| `wantsurl` | text | абсолютный URL внутри `wwwroot`, куда вести после входа |
| `timecreated` | int | когда запрошено |
| `timeused` | int | когда использовано, `0` — ещё нет |
| `ip` | char(45) | IP запроса |

Индексы: `tokenhash`, `emailhash+timecreated`, `ip+timecreated`, `userid`, `timecreated`.

## Изоляция

- Плагин **не аутентифицирует по паролю**: `user_login()` всегда `false`,
  `is_internal()` → `false`, `prevent_local_passwords()` → `false`,
  `can_change_password()` / `can_reset_password()` / `can_signup()` / `can_confirm()` → `false`.
- **Пароли и `auth` пользователей не трогаются вообще**: у студентов остаётся
  `manual`/`email`, их пароли как были, так и есть; «Забыли пароль?» работает штатно.
  `can_be_manually_set()` → `false`: админ не может назначить `kabmagic` как метод
  аутентификации пользователю, у плагина нет «своих» пользователей.
- Вход — только `complete_user_login()` для аккаунта, прошедшего те же проверки, что
  штатный вход (удалён / заблокирован / не подтверждён / метод из списка и включён).
- Кнопка на странице входа — штатный механизм `loginpage_idp_list()`, вёрстка ядра
  (`core/loginform`), никаких патчей ядра и темы.
- С WP-плагином `kab-magic-link-auth`, `auth_telegram_wp` и `auth_kabtarget` не связан
  и их не касается; работает независимо от `alternateloginurl` (прямая ссылка на
  `request.php` действует, даже пока страница входа ещё перебрасывает на WordPress).

## Внешние зависимости

Только почта Moodle — `email_to_user()` с настроенным SMTP (на проде SendGrid,
`smtphosts`). Письмо уходит с заголовком `X-SMTPAPI: {"category":["moodle-magic"]}`
(через `customheaders` отправителя, как у патча `fc8cfd9` для форумов) — статистика
по входам видна в SendGrid → Stats → Category Stats. Больше ничего внешнего нет:
ни WordPress, ни сторонних API.

## Настройки (Администрирование → Плагины → Аутентификация → Вход по ссылке на почту)

| Настройка | По умолчанию | Что |
|---|---|---|
| `lifetime` | 15 | срок действия ссылки, минут |
| `ratelimit` | 3 | запросов на адрес за окно (на IP — ×10) |
| `ratewindow` | 5 | окно лимита, минут |
| `allowedauths` | `manual, email` | каким методам аутентификации разрешён вход по ссылке |

## Что учтено по безопасности

- Токен 256 бит, в БД только хеш; одноразовый; срок 15 минут; гасится до повторной
  проверки аккаунта, так что умирает при первом использовании в любом случае.
- Одинаковый ответ формы для любого адреса. Оговорка: время ответа всё же отличается
  (письмо отправляется синхронно через SMTP), по нему существование адреса в принципе
  можно угадать — как и у штатного «Забыли пароль?».
- Рейт-лимит по адресу и по IP; строки для чужих адресов тоже считаются.
- `wantsurl` — только внутри сайта (`PARAM_LOCALURL` + проверка префикса `wwwroot`).
- Токен не попадает в `$PAGE->url` (не утекает в ссылки страницы), на странице входа
  `Referrer-Policy: no-referrer`; в POST токен идёт в теле.
- Промежуточная страница с POST защищает от сканеров ссылок; `sesskey` в POST — от
  подстановки чужой формы. Сканер, исполняющий JS, ссылку всё равно погасит — тогда
  пользователь увидит «недействительна» и запросит новую.

## Установка без CLI (dataroot не писабелен, PHP в вебруте не исполняется)

1. Залить каталог под юзером сайта (из LF-исходников; с Windows — через `tar`, чтобы не
   занести CRLF):
   ```bash
   tar -C public/public/auth -czf /tmp/auth_kabmagic.tgz kabmagic
   scp /tmp/auth_kabmagic.tgz web-18:/tmp/
   ssh web-18 "tar -C /sites/edu.kabacademy.com/public/public/auth -xzf /tmp/auth_kabmagic.tgz && rm /tmp/auth_kabmagic.tgz"
   ```
2. Установка через локальный HTTP (логин не нужен, upgradekey не задан):
   ```bash
   ssh web-18 "curl -s -H 'Host: edu.kabacademy.com' -H 'X-Forwarded-Proto: https' 'http://127.0.0.1/admin/index.php?confirmrelease=1' | grep -o 'status-new[^<]*<[^>]*>[^<]*' "
   ```
   — убедиться, что `status-new` только у `auth_kabmagic`, остальные `uptodate`; затем тот же
   URL с `&confirmplugincheck=1&cache=0` — создаст таблицу и зарегистрирует задачу.
   Настройки получают значения по умолчанию при установке; если Moodle всё же откроет
   `/admin/upgradesettings.php` — сохранить как есть.
3. **Включить плагин**: Администрирование → Плагины → Аутентификация → Управление
   аутентификацией → «Вход по ссылке на почту» → глаз. Порядок кнопок на странице входа =
   порядок включённых методов (стрелки там же). Нужна сессия админа (MFA).
   На dev то же делается SQL-ом `UPDATE mdl_config SET value = CONCAT(value, ',kabmagic')
   WHERE name = 'auth'` **до** шага 2 — установка сама сбрасывает кэш конфигурации.
4. Проверка: `/login/index.php` показывает кнопку; `/auth/kabmagic/request.php` открывает
   форму; после отправки — строка в `mdl_auth_kabmagic_tokens` с `tokenhash`, письмо
   в ящике с темой «Вход на Kabacademy»; переход по ссылке → `/my/` под пользователем,
   `timeused` заполнен, повторный переход — «недействительна».
5. После апгрейда Moodle — проверить, что каталог `auth/kabmagic` жив и плагин не
   «missing from disk» (кнопка исчезнет молча).

## Диагностика

```sql
-- последние запросы: кто, когда, использовано ли
SELECT id, userid, FROM_UNIXTIME(timecreated) t, FROM_UNIXTIME(NULLIF(timeused,0)) used, ip,
       tokenhash <> '' AS linkissued
  FROM mdl_auth_kabmagic_tokens ORDER BY id DESC LIMIT 20;
-- сколько писем ушло за сутки
SELECT COUNT(*) FROM mdl_auth_kabmagic_tokens WHERE tokenhash <> '' AND timecreated > UNIX_TIMESTAMP() - 86400;
```

Письмо не пришло: адрес не у аккаунта с `manual`/`email` (`SELECT auth, suspended,
confirmed FROM mdl_user WHERE email = '…' AND deleted = 0`), лимит (3 за 5 минут),
или `noemailever`/`divertallemailsto` в `config.php` (на dev письма выключены —
проверять по строке в таблице).

## Грабли

- Dev-площадка: `noemailever = true` — письмо не уходит, но строка с хешем пишется;
  ссылку для проверки входа можно подложить самому: сгенерировать 32 байта, положить
  `SHA-256` в `tokenhash`, в URL — base64url без `=`.
- `is_enabled_auth('kabmagic')` смотрит в `$CFG->auth` из кэша конфигурации; правка
  `mdl_config` SQL-ом без сброса кэша не подействует (на проде — только через UI).
- Кнопка рисуется шаблоном ядра `core/loginform` под заголовком «Войти с помощью»
  (строка `potentialidps`) — там же, где кнопка Telegram.
