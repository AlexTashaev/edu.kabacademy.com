# local_kabfeedbackgdoc — ответы «Обратной связи» → Google-таблицы

Каждый отправленный ответ в активности **Обратная связь** (mod_feedback) уходит
POST-ом в веб-приложение Google Apps Script и становится строкой Google-таблицы.
Куда и в каком виде — решает Moodle, по настройкам плагина:

| Что за форма | Куда | Раскладка |
|---|---|---|
| прошла три фильтра (курс, название, cmid) — формы «Вопрос по теме урока N…» | таблица вопросов, одна на все такие формы | как в таблицах «Задать вопрос преподавателю … (Ответы)» |
| перечислена в «Формы со своей таблицей» | своя таблица | одна колонка на каждый пункт формы |
| всё остальное | никуда | — |

**Что сейчас куда идёт**, очередь отправки и кнопка «Отправить все ответы заново» —
на странице состояния: *Администрирование → Плагины → Локальные плагины →
Обратная связь → Google-таблица: что куда идёт* (`/local/kabfeedbackgdoc/index.php`).
Если форма не пересылается, там это видно сразу: она серая.

## Раскладки

**Таблица вопросов** (`questions`):

`Отметка времени | Имя | Город | Буду участвовать в вебинаре | Мой вопрос | Номер группы | Email | Ссылка в Moodle | Форма | Ответ преподавателя`

Город — из профиля пользователя, «Номер группы» — группы курса, в которых он состоит.
Пункты формы раскладываются по колонкам по названию (`COLUMN_RULES` в скрипте):
«присутств/участв» → участие, «вопрос» → вопрос, остальное дописывается к вопросу.
Преподаватели отвечают в колонке «Ответ преподавателя».

**Своя таблица** (`generic`):

`Отметка времени | Имя в Moodle | Email | <пункт 1> | … | <пункт N> | Группа в Moodle | Ссылка в Moodle`

Колонки скрипт создаёт сам при первой записи. Появился в форме новый пункт — его
колонка добавится справа.

**С таблицами можно работать руками.** Скрипт находит колонку не по месту и не по
заголовку, а по примечанию к ячейке заголовка (`moodle:item152`, `moodle:time`, …).
Поэтому заголовки можно переименовывать, колонки — двигать, между ними вставлять свои.
Нельзя только стирать эти примечания. Последняя, скрытая колонка «ID ответа» — ключ
для защиты от дублей, её не трогать.

## Как это устроено

```
студент отправляет форму
  → \mod_feedback\event\response_submitted
  → observer: sender::target_for() — пересылается ли форма → adhoc-задача
  → cron: sender::build_payload() → curl POST JSON → Apps Script doPost()
  → скрипт дописывает строку в таблицу из payload.target
```

- Отправка **не** делается в запросе студента: observer только ставит adhoc-задачу,
  cron шлёт и при ошибке ретраит с back-off.
- Доставленным считается только ответ-JSON с `"ok": true`. Сломанный скрипт или
  развёртывание, у которого слетел доступ «Все», отвечают HTML-страницей с кодом 200 —
  это ошибка, задача уйдёт на повтор.
- Ответы отдаются через `feedback_item_base::get_printval()`, т.е. для multichoice
  приходит текст варианта, а не индекс.
- Ячейке с текстом сначала ставится формат «обычный текст», потом пишется значение.
  Иначе Google разбирает ответ как набранный с клавиатуры (rich text от этого не
  спасает): телефон `+7999…` становится числом и теряет плюс, `=HYPERLINK(…)` от
  студента — живой формулой, `12:30` — временем.

**Дубли.** Ключ строки — id ответа и метка времени, `r2631t1790336304`, хранится в
скрытой колонке самой таблицы (буквы в ключе нужны: `2631:1790336304` Google читает
как длительность). Ретрай cron той же доставки и повторная «Отправить все заново» строк не
добавляют. Метка времени входит в ключ не случайно: у неанонимной «Обратной связи»
«Разрешить несколько отправок» означает *редактирование* прошлого ответа (та же запись
`feedback_completed`, новый `timemodified`), и отредактированный ответ должен лечь
новой строкой.

**Редиректы.** Apps Script отвечает на POST 302 → `script.googleusercontent.com`, который
принимает только GET. Moodle-curl при эмуляции редиректов (open_basedir) повторяет POST и
получает 405, поэтому `sender::request()` не следует за редиректом, а сам делает GET по `Location`.

## Настройки

*Администрирование → Плагины → Локальные плагины → Обратная связь → Google-таблица (KAB)*

| Настройка | Что |
|---|---|
| `enabled` | вкл/выкл |
| `webhookurl` | URL развёртывания Apps Script `…/exec` |
| `secret` | строка, совпадающая с `SECRET` в `Code.gs` (пусто = без проверки) |
| `courseids` | через запятую id курсов — пересылать все feedback из них; пусто = любой курс |
| `namepattern` | регулярка (без регистра) на название активности, напр. `вопрос`; пусто = любое |
| `cmids` | через запятую cmid активностей (параметр `id` в URL); пусто = не ограничивать |
| `defaulttarget` | ссылка на таблицу вопросов; пусто = та, что прописана в скрипте (`SPREADSHEET_ID`) |
| `routes` | формы со своей таблицей, по строке на форму: `cmid = ссылка на таблицу` (необязательно `\| имя листа`) |

Три фильтра AND-ятся и относятся только к таблице вопросов. Рабочая настройка:
`courseids = 236,238`, `namepattern = вопрос`, `cmids` пусто — новая еженедельная форма
«Вопрос по теме урока N…» подхватывается без правки настроек. Форма из `routes`
пересылается независимо от фильтров.

### Новый семестр

- Новый курс — дописать его id в `courseids`.
- Новая таблица вопросов — создать, назвать с пометкой `(Moodle)`, вставить ссылку в `defaulttarget`.
- Форме нужна своя таблица — создать пустую таблицу с `(Moodle)` в названии, дописать
  строку в `routes`, на странице состояния нажать «Отправить все ответы заново», если в
  форме уже есть ответы.

Скрипт при этом трогать не нужно. Два условия к любой таблице: в названии есть
`(Moodle)` (так скрипт не запишет в постороннюю таблицу по ошибочной ссылке) и аккаунт,
от имени которого развёрнут скрипт, может её редактировать.

## Установка Apps Script (один раз)

1. script.google.com → *Создать проект*, вставить [apps_script/Code.gs](apps_script/Code.gs),
   задать `SECRET` и `SPREADSHEET_ID` (таблица вопросов).
2. *Начать развёртывание → Новое развёртывание → Веб-приложение*:
   *Запуск от имени:* я; *У кого есть доступ:* все. Авторизовать. Скопировать URL `…/exec`.
3. Вставить URL и секрет в настройки плагина.
4. Проверка без Moodle: запустить `testInsert` в редакторе скрипта — в таблице появится
   тестовая строка (потом удалить).

**Обновление скрипта.** Блок настроек в начале файла (до строки `settings end`) не трогать —
там секрет; заменить всё, что ниже. Затем *Управление развёртываниями → карандаш →
Новая версия*, иначе `/exec` продолжает исполнять старую. Какая версия работает —
показывает `GET <webhookurl>` и кнопка «Проверить связь со скриптом» на странице состояния.

Логика скрипта проверяется без Google: `node apps_script/test_local.js`.

## Формат payload

```json
{
  "event": "feedback_response",
  "site": "https://edu.kabacademy.com",
  "completedid": 123,
  "timestamp": 1790000000,
  "datetime": "23.09.2026 14:05",
  "target":   {"spreadsheet": "", "sheet": "", "layout": "questions"},
  "course":   {"id": 236, "shortname": "...", "fullname": "..."},
  "feedback": {"id": 34, "cmid": 13448, "name": "...", "url": ".../mod/feedback/view.php?id=13448"},
  "anonymous": false,
  "user": {"id": 8, "fullname": "...", "email": "...", "city": "Хайфа", "groups": ["11ж"], "url": ".../user/view.php?id=8&course=236"},
  "responseurl": ".../mod/feedback/show_entries.php?id=13448&userid=8&showcompleted=123",
  "answers": [{"itemid": 165, "name": "...", "type": "multichoice", "value": "в 17:00 изр"}],
  "secret": "..."
}
```

`target.spreadsheet` пустой = таблица из `SPREADSHEET_ID` скрипта. «Отправить все заново»
шлёт пачками по 50: `{"event": "feedback_batch", "responses": [ …такие же объекты… ]}`,
скрипт дописывает строки в том же порядке.

## Диагностика

- Страница состояния: очередь, последние отправки и что на них ответил скрипт.
- Очередь в БД: `SELECT * FROM mdl_task_adhoc WHERE component = 'local_kabfeedbackgdoc'` —
  `faildelay > 0` значит доставка не удалась, текст ошибки в `mdl_task_log.output`.
- `GET <webhookurl>` должен вернуть `{"ok":true,"ping":"local_kabfeedbackgdoc","version":5}`.
- Ошибка `в названии таблицы нет пометки (Moodle)` — таблицу переименовали или в настройках
  ссылка не на ту таблицу.
