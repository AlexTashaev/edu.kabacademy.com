# local_kabdarkmode — светлая, тёмная или авто

Переключатель оформления, как «день/ночь» в мобильных приложениях. Значок в шапке рядом с
сообщениями открывает меню из трёх пунктов:

| Режим | Что делает |
|---|---|
| **Светлое** | всегда светлое оформление |
| **Тёмное** | всегда тёмное |
| **Авто** | тёмное с `darkfrom` до `darkto` (по умолчанию 20:00–7:00) по часам устройства, днём светлое; переключается само, без перезагрузки страницы |

## Spec

**Цель.** Дать студенту выбрать тёмное оформление на всём сайте (кабинет, курс, уроки, тесты,
форумы, страница входа) без смены темы Moodle и без правок ядра.

**Как устроено.**

1. Хук `before_standard_head_html_generation` вставляет в `<head>` крошечный скрипт (~450 байт):
   читает выбор из cookie `kabdm_mode`, считает итог для «Авто» и ставит на `<html>`
   `data-bs-theme="light|dark"` и `data-kabdm-mode="light|dark|auto"` — до отрисовки страницы,
   поэтому белой вспышки нет.
2. `data-bs-theme="dark"` включает тёмную палитру Bootstrap 5.3 — она уже скомпилирована в CSS
   Boost (Moodle 5.x): карточки, меню, модальные окна, формы, таблицы, алерты.
3. Остальное Moodle рисует цветами, вшитыми при компиляции SCSS (каркас страницы, панели,
   индекс курса, вкладки, вопросы теста, сообщения), плюс брендинг из настройки
   `theme_boost/scss` в БД и классы `.kab-*` темы kabacademy. Это перекрывает `styles.css`
   плагина. **Все** его правила, кроме самого переключателя, начинаются с
   `html[data-bs-theme="dark"]` — в светлом режиме плагин не меняет ни одного пикселя.
4. Значок и меню выводит `local_kabdarkmode_render_navbar_output()` (место для плагинов в шапке,
   там же сообщения и уведомления). Какой значок виден и где стоит галка — решает CSS по
   `data-kabdm-mode` на `<html>`, так что сервер не должен знать выбор.
5. Хук `before_footer_html_generation` вставляет скрипт меню: клик по пункту → cookie →
   атрибуты на `<html>`; раз в минуту и при возврате на вкладку пересчитывает «Авто» и заодно
   подхватывает выбор, сделанный в соседней вкладке.
6. Старый контент уроков с инлайн-цветами (`color: rgb(51, 51, 51)`, `color: #3C5D90`, белая
   подложка) в тёмном режиме подсвечивается правилами по `[style*=…]` внутри `#page`, иначе
   тёмный текст пропадает на тёмном фоне.

**Где хранится выбор.** Только в браузере устройства — cookie `kabdm_mode` на год
(`path=/`, `SameSite=Lax`, `Secure`), как в мобильных приложениях: на телефоне можно держать
«Авто», на компьютере «Светлое». На сервере плагин ничего не хранит, таблиц нет. Режим работает
и до входа (страница входа, витрина). Cookie отключены — выбор живёт до перехода на другую
страницу, дальше режим по умолчанию.

**Почему не `localStorage`.** Ядро (`lib/amd/src/storagewrapper.js`) вызывает
`localStorage.clear()` при каждой смене `jsrev`, то есть после любой «Очистки кэшей» и любого
апгрейда — выбор всех студентов сбрасывался бы. Проверено на dev 23.11.2026.

**Настройки** («Администрирование → Плагины → Локальные плагины → Тёмная тема»):

| Настройка | По умолчанию | |
|---|---|---|
| `enabled` | да | выключить — значок пропадает, у всех светлое оформление |
| `defaultmode` | `light` | режим тех, кто ещё не выбирал |
| `darkfrom` / `darkto` | 20 / 7 | часы тёмного оформления в режиме «Авто»; равны — «Авто» всегда светлое |

Настройки не сохранены (`upgradesettings` не пройден) — код берёт значения по умолчанию.

## Изоляция

- Тему Moodle, ядро и другие плагины не трогает: только хуки ядра, navbar-колбэк и
  `styles.css`, который Moodle сам подключает в CSS любой темы.
- Работает и с Boost (сайт на проде), и с дочерней `theme_kabacademy` (dev целиком, курсы 236/238
  на проде): обе собирают один и тот же Bootstrap.
- Выключение — настройка `enabled` или удаление плагина. Таблиц нет, удаление ничего не теряет.

## Внешние зависимости

- Bootstrap 5.3 с `$enable-dark-mode: true` и `$color-mode-type: data` — так в Moodle 5.0+.
  Апгрейд Moodle сменит Bootstrap или выключит color modes — проверить, что
  `[data-bs-theme=dark]` остался в скомпилированном CSS.
- Классы и селекторы Moodle (`#page.drawers .main-inner`, `.drawer`, `.courseindex-item`,
  `.moremenu`, `.que .formulation` и др.) — после апгрейда Moodle пройтись по чек-листу ниже.
- Брендинг из `theme_boost/scss` (БД) и `theme/kabacademy/scss/kab.scss`: новый цвет там —
  проверить, читается ли он в тёмном режиме, при необходимости дописать в `styles.css`.
- Bootstrap-дропдаун (`data-bs-toggle="dropdown"`) из ядра — меню открывается им.
- Не покрыто: TinyMCE (редактор остаётся светлым островом), H5P и другие iframe, виджет чата,
  картинки с прозрачным фоном и тёмными линиями.

## Установка без CLI

1. Залить каталог в `public/public/local/kabdarkmode` (с Windows — только
   `git -c core.autocrlf=false -c core.eol=lf archive`, рабочая копия отдаёт CRLF).
2. `curl -H "Host: <сайт>" -H "X-Forwarded-Proto: https" "http://127.0.0.1/admin/index.php?confirmrelease=1"`
   → на странице проверки плагинов `status-new` только у нашего.
3. Тот же URL с `&confirmplugincheck=1&cache=0` — ставит и чистит кэши (логин не нужен).
4. Правка только `styles.css` без смены версии — «Очистить кэши → Темы» в админке.

## Чек-лист проверки (тёмный режим)

Кабинет `/my/`, «Мои курсы», страница курса с индексом курса, урок (lesson), книга, страница,
тест (попытка и разбор), форум, профиль, календарь, сообщения (правая панель), уведомления,
страница входа, меню пользователя, модальное окно, телефон (375 px) — текст читается, белых
плашек нет. Затем «Светлое» — всё как до плагина. «Авто» — сменить `darkfrom`/`darkto` так,
чтобы текущий час попал в интервал, и дождаться переключения без перезагрузки.

## Откат

Выключить `enabled` (мгновенно) или удалить плагин в «Обзоре плагинов». Cookie `kabdm_mode`
студентов останется, но без плагина его никто не читает.
