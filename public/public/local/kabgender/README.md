# local_kabgender — автоопределение пола по имени

## Спека

**Задача.** При регистрации пользователя (создание аккаунта из WP через Edwiser
Bridge / core_user_create_users, email-саморегистрация, ручное создание) и при
записи на курс автоматически определять пол по имени/фамилии и записывать его в
кастомное поле профиля `gender` (меню «муж/жен», fieldid 2 на проде).

**Механизм.** Локальный плагин с двумя обсерверами событий:

- `\core\event\user_created` — новые аккаунты (все пути, где событие не подавлено);
- `\core\event\user_enrolment_created` — страховка для путей с подавленным
  событием создания (напр. `auth_edwiserbridge` cohort-flow вызывает
  `user_create_user($user, 1, false)`) + ленивое дозаполнение старых
  пользователей при их следующей записи на курс.

Оба обсервера идемпотентны: пишут только если поле пусто. Ошибки глотаются
(try/catch) — регистрация/запись никогда не ломается из-за детектора.

**Детектор** (`classes/detector.php`, чистый PHP без зависимостей от Moodle,
тестируется автономно):

1. Нормализация: первый токен имени, lowercase, ё→е, і/ї→и, є→е, ґ→г,
   апострофы убираются.
2. Приоритет сигналов: словарь исключений имени → эвристика окончания имени
   (кириллица: -а/-я = жен, согласная/-й = муж; латиница: -a/-ia = жен,
   согласная/-y/-ii/-iy = муж) → суффикс фамилии (-ова/-ева/-ина/-ая… = жен;
   -ов/-ев/-ин/-ий… = муж; унисекс -енко/-ук/-ко/-ич не используются).
   Фамилия идёт после окончания имени, чтобы унисекс-фамилии (Литвин, Волошин,
   Цой) не перебивали явное окончание имени.
3. Словари покрывают исключения: мужские на -а/-я/-о/-ь (Никита, Илья, Микола,
   Дмитро, Игорь, Шауль…), женские на согласную/-ь (Любовь, Айгуль, Эстер,
   Гульназ…), уменьшительные, ивритские, тюркские, латинские транслитерации.
4. Неоднозначные имена (Саша, Женя, Валя, Слава, Шура) решаются только по
   фамилии, иначе пол не ставится.
5. Нет уверенности — поле остаётся пустым. Тестовые имена (test, тест, admin,
   demo…) игнорируются.

**Изоляция и внешние зависимости.** Плагин ничего не требует от других плагинов;
пишет напрямую в `user_info_data` (fieldid по shortname `gender`), значение
валидируется по опциям меню из `user_info_field.param1`. Если поле удалят или
переименуют — обсерверы молча выходят. Событий при записи не порождает (нет
риска рекурсии).

**Установка.** Разложить в `public/local/kabgender`, зайти в админку →
Уведомления → обновить базу (CLI на сервере недоступен под ssh-юзером).
