# local_kabwporders — оплаты старого сайта (WordPress)

Реестр оплаченных заказов kabacademy.com до переезда в Moodle: **кто, когда, за что и сколько
заплатил**. Нужен, чтобы история оплат не пропала, когда WordPress выключат.

Спека и скрипт выгрузки — в приватном репозитории `AlexTashaev/kabacademy.com`:
`.claude/analysis/spec_payment_archive_2026-11.md`, `tools/payment-archive/`.

## Что внутри

| | |
|---|---|
| `local_kabwporders_order` | заказ: номер заказа WordPress, человек в Moodle, почта и имя плательщика, даты, статус, сумма, валюта, возврат, шлюз, номер транзакции |
| `local_kabwporders_item` | позиции: товар, количество, сумма строки, курсы Moodle, к которым товар был привязан |
| «Оплаты старого сайта» (`index.php`) | поиск по номеру заказа, почте, имени, номеру транзакции; фильтры; итоги для сверки; CSV |
| «Импорт оплат старого сайта» (`import.php`) | загрузка выгрузки |
| `\local_kabwporders\api::for_user()` | оплаты человека в том виде, в каком их ждёт карточка `local_kabperson` |
| `myorders::render($USER)` и `my.php` | блок «Прежние оплаты» для самого студента: номер заказа, дата, за что, сумма, способ оплаты. Касса `local_kabshop` выводит его в «Моих заказах»; без кассы та же таблица — на `my.php` |

Оба пункта меню — «Администрирование → Курсы». Права: `local/kabwporders:view` и
`local/kabwporders:import`, по умолчанию у менеджера.

Студент видит только свои оплаты: привязанные к его пользователю и гостевые, оплаченные с его
почты. Номер транзакции, почта и имя плательщика ему не показываются.

Чего в реестре нет: номеров и токенов карт, номеров удостоверений, адресов, телефонов, IP,
неоплаченных и нулевых заказов.

## Изоляция

- Плагин только хранит и показывает. Он не записывает в курсы, не выдаёт доступ, не участвует в
  оплате и не зависит от `local_kabshop`.
- Импорт не создаёт и не правит пользователей Moodle. Человека не нашёл — заказ остаётся с
  `userid = 0` и ищется по почте плательщика.
- Импорт заменяет реестр целиком в одной транзакции: повторный запуск не даёт дублей, при
  ошибке прежние данные остаются.
- Удаление плагина удаляет обе таблицы. Источник данных до выключения WordPress — сам WordPress.

## Установка (CLI Moodle на площадке не работает)

1. Скопировать каталог в `public/local/kabwporders` (docroot Moodle).
2. Открыть `/admin/index.php` под администратором — Moodle создаст таблицы.

## Импорт

Выгрузку делает `tools/payment-archive/export.sh` (три файла `orders.tsv`, `items.tsv`,
`products.tsv`; в них почта и имена — в git не класть).

Два способа:

- **Загрузкой.** «Импорт оплат старого сайта» → положить три файла → «Импортировать». Если
  лимит загрузки мал, сжать: `gzip -k orders.tsv` — форма принимает `.tsv.gz`. Загруженные
  файлы после импорта удаляются.
- **Из каталога на сервере.** В `config.php` указать каталог вне docroot:
  `$CFG->local_kabwporders_importdir = '/путь/к/каталогу';` и положить туда три файла. На
  странице импорта появится кнопка «Импортировать из каталога на сервере». После импорта файлы
  удалить руками, строку из `config.php` убрать.

Человек определяется так: сначала по связке из WordPress (`moodle_user_id`), если такой
пользователь есть и не удалён; иначе по почте плательщика.

## Сверка

Страница импорта после запуска показывает счётчики, страница реестра — итоги по валютам. Их
сравнивают с тем, что напечатал `export.sh`: число заказов, суммы и возвраты по каждой валюте
должны совпасть.

## Откат

Удалить плагин в «Плагины → Обзор плагинов» — таблицы удалятся. Данных Moodle он не трогал.
